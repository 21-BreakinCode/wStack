## Items

1. Cross-repo refs in `scripts/contract-ref-shift.sh`. Today it prints `unchecked: <ref>: cross-repo` for each ref of the form `<owner>/<repo>@<commit>:path:lines`. Find the local clone of that repo the same way `contract-refs.sh` does. Its `clone_for` reads `workspace_root` and the Service Mapping from the initiation file, and takes `--mapping-from`. Move that lookup into `scripts/lib/contract-refs-read.sh` so both scripts share it. For a cross-repo ref with a clone, compare the ref's commit with the clone's `HEAD`:
   - The file changed between them: print `changed: <ref>`.
   - The file did not change and `HEAD` differs: print `shift: <ref> -> <owner>/<repo>@<HEAD sha>:path:lines`. The agent can then write the new commit into the draft.
   - `HEAD` equals the ref's commit: count it as unchanged.
   - No clone: print `unchecked: <ref>: no local clone of <owner>/<repo>`. Unknown commit in the clone: print `unchecked: <ref>: unknown commit`.
   - The count line becomes `refs: <c> changed, <s> shifted, <u> unchanged, <x> unchecked`.
   - The script does not fetch. Update the reuse rule in `skills/start-task/references/execute.md` to say: fetch the clones first, then run the script, re-read each `changed:` ref, and write each `shift:` commit.
   - Test in `tests/test_contract_ref_shift.sh`: a temp workspace with an initiation file and a second repo clone whose HEAD moved, with one cited file changed and one not.

2. Center the diagrams on the page (`scripts/contract_render.py` CSS). The user wants a Notion-style single column. The figure, its caption, its key, and the part cards stay in the 760 px `main` column. Each SVG is centered on the column axis at its full size. An SVG wider than the column extends equally on both sides, up to `min(1200px, calc(100vw - 32px))`, and does not scale down. Part cards use at most 2 columns inside the column (`repeat(auto-fill, minmax(340px, 1fr))`), with `align-items: start`, so a short card leaves no tall empty box. Test in `tests/test_contract_render.sh`: the CSS rules are on the page. Also check in a browser at 1366 px width (serve the page over http, as `scripts/check-page-width.sh` does): each SVG's horizontal center is within 1 px of the `main` column's center, and the page has no sideways scroll. Record that check in the report.

3. Space the states markers near one box side. In the media lifecycle, two markers sit about 4 px apart at the left edge of `failed`: marker 2 (pending to failed) and marker 7 (failed to pending). Their curves bunch together. Markers near one box side keep at least an 8 px gap between their circles. Neighbor curves stay apart where they meet the side. Staggering the markers along their curves or spacing the ends further apart are both fine. Test: across `state_fixtures()` and the media lifecycle, any two markers keep an edge gap of at least 8 px. The media lifecycle stays at most 600 px wide.

4. Elbow implements lines between neighbor layers. Today such a line is a straight line from the adapter's bottom center to the port's top center, so it is often slanted. Draw it as an elbow: down from the adapter, across in the gap between the two pill rows, then down into the port. Two elbows in one gap use different heights, 8 px apart (`LANE_PITCH`), and nest so they do not cross. A pair in one pill row keeps its curve. A perfectly vertical pair stays a straight line. This changes the basic fixture picture, so update `SVG_ARCHITECTURE_SHA256` on purpose and say so in the commit message. Test: every implements path between neighbor layers has only horizontal and vertical segments. No path crosses a pill. Two elbows in one gap do not cross.
