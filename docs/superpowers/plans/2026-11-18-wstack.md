# wStack v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the wStack Claude Code plugin: one fixed pipeline (launch, Confirmation, Execute, Verify, Deliver, retro) that runs each task in its own herdr workspace, with a guard hook, preflight checks, evidence handling, and an Excalidraw review page.

**Architecture:** The repository root is the plugin root. Deterministic work lives in small bash scripts under `scripts/` with bash tests under `tests/`. Agent behavior lives in skills and agents (Markdown), tested with `claude plugin eval` cases under `evals/`. Skills call scripts through `${CLAUDE_PLUGIN_ROOT}/scripts/...`.

**Tech Stack:** bash 3.2-compatible scripts, jq, herdr 0.9.5, Claude Code 2.1.327 plugins (skills, agents, hooks, userConfig, dependencies), `@playwright/cli@0.1.24`, `cf@1.0.0-rc.1`, ffmpeg, cwebp, sips, VHS, answer-me-with-html.

**Spec:** `docs/spec.md` (base, version 1.0) and `docs/superpowers/specs/2026-11-18-wstack-design.md` (changes). Where they disagree, the design wins. Read both before any task.

## Global Constraints

- Plugin `name`: `wstack`. `displayName`: `wStack`. Version `0.1.0` in both `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
- Marketplace name `wstack`, one plugin entry with `"source": "./"`, and `"allowCrossMarketplaceDependenciesOn": ["answer-me-with-html"]`.
- `plugin.json` has `"dependencies": ["answer-me-with-html@answer-me-with-html"]`.
- Minimum versions: Claude Code 2.1.51, gh 2.99.0, Node accepted by cf (`^22.23.0 || ^24.22.0 || ^26.12.0`). Pinned: `@playwright/cli@0.1.24`, `cf@1.0.0-rc.1`.
- Scripts: `#!/usr/bin/env bash`, `set -euo pipefail`, compatible with `/bin/bash` 3.2 (no `mapfile`, no associative arrays, no `${var,,}`). Every path variable is quoted, because vault paths can contain spaces.
- Skills and agents reference bundled files only as `${CLAUDE_PLUGIN_ROOT}/...`. Scripts that source a sibling resolve it with `$(dirname "${BASH_SOURCE[0]:-$0}")`.
- Slug regex: `^[a-z][a-z0-9-]{0,31}$`. Task id: `<YYYY-MM-DD>-<slug>`.
- Status values, exactly: `drafting`, `awaiting-approval`, `executing`, `waiting-user`, `verifying`, `awaiting-deliver-approval`, `delivered`, `cancelled`.
- Frontmatter format (my call, recorded in `docs/decisions.md` in Task 2): one `key: value` per line, no inline comments, and every list value is one-line JSON (`stopped_for_user: []`, `targets: [{"target":"pr","url":"...","undo":"..."}]`). This keeps the frontmatter valid YAML and parseable with jq.
- Evidence working folder: `/tmp/wstack-evidence/<task_id>/`. Non-code task working directory: `~/.wstack/tasks/<task_id>/`.
- Tests never write into `$HOME/Projects/LifeOS/`, never touch the user's main herdr session, and use fake `gh` and `cf` binaries on `PATH` whenever a guarded command runs.
- Documents and skill prose follow the user's simple-english rules. Skills follow `/Users/williamhung/.claude/plugins/marketplaces/21-breakincode/.claude/rules/writing-great-skills.md`.
- `start-task` and `retro` are user-invoked (`disable-model-invocation: true`). `review-page`, `evidence`, and `deliver` are helper skills (`user-invocable: false`).
- Commit format: `<type>: <description>`, types feat, fix, refactor, docs, test, chore. End every commit message with the two attribution lines the controller gives you. Work on branch `feat/v0.1`. Never push to `main`. Never create or merge a pull request without the user's approval.
- Eval runs use `--runs 1 --trust-plugin` to save cost, unless a task says otherwise. Eval cases that need fixtures (a throwaway vault, a temp git repo, fake binaries) build them in their `scaffold_script`, and run with `--scaffold`.

## Review Focus

1. A rough idea in Chinese or with punctuation ("修 login 逾時!") must still give a valid ASCII slug. Test: Task 6, eval case `launch-non-ascii-idea`.
2. A vault path or `tasks_dir` with a space ("/tmp/wstack test vault") must work in every script. Test: Task 2 and Task 16 fixtures use a space in the vault path.
3. Guarded commands hidden in compound forms (`cd x && gh pr merge 1`, `bash -c 'gh pr merge 1'`, `FOO=1 gh pr merge 1`) must still be caught. Test: Task 4 matrix.
4. API logs with header names in any case (`authorization:`, `COOKIE:`), `Set-Cookie`, `x-api-key`, and `?api_key=` in a URL must be redacted. Test: Task 11 `test_redact_log.sh`.
5. A pull request video that cannot fit under `pr_media_max_mb` even at the smallest step must fail with a clear message, not loop. Test: Task 11 `test_compress_media.sh`.

### Task 5: herdr launcher and resume scripts

**Files:**
- Create: `scripts/launch-task.sh`, `scripts/list-open-tasks.sh`, `scripts/resume-task.sh`
- Test: `tests/test_launch_task.sh`, `tests/test_list_open_tasks.sh`, `tests/test_resume_task.sh`, `tests/fixtures/bin/herdr` (fake that logs arguments and prints canned JSON in the shapes that S5 recorded)

**Interfaces:**
- Consumes: `fm_get`, `fm_set` (Task 2). S5 JSON paths.
- Produces: `bash scripts/launch-task.sh --task-dir <abs> [--repo-path <abs>] [--mobile]`. It reads `task_id` and `work_type` from `spec.md`, takes the slug from `task_id` (everything after the first 11 characters), and exits 3 with "not running inside herdr" when `HERDR_ENV` is not `1`. Steps, in order:
  1. Code task with `--repo-path`: `herdr worktree create --cwd <repo> --branch wstack/<slug> --label <slug> --no-focus`. Otherwise: `mkdir -p ~/.wstack/tasks/<task_id>` and `herdr workspace create --cwd ~/.wstack/tasks/<task_id> --label <slug> --no-focus`.
  2. `fm_set spec.md workspace_cwd <worktree or task dir>`.
  3. `herdr agent start <slug> --kind claude --pane <root pane> -- <CLAUDE_TASK_FLAGS>`, where `CLAUDE_TASK_FLAGS` is `--remote-control <slug> --name <slug> --permission-mode bypassPermissions` plus anything S1 said it needs.
  4. `herdr agent prompt <slug> "/wstack:start-task --task <task_id>[ --mobile]"` (bare `/start-task` if S10 said `bare-works`).
  5. `herdr workspace focus <workspace id>`.
  6. Prints `{"workspace_id":"...","agent":"<slug>","cwd":"..."}`.
  If the herdr agent name is taken (`herdr agent get <slug>` succeeds), it exits 4 with "agent name taken". The skill then picks the next slug.
- Produces: `bash scripts/list-open-tasks.sh --vault <abs> --tasks-dir <rel>`. It prints TSV lines `task_id<TAB>status<TAB>workspace_cwd<TAB>folder`, for statuses other than `delivered` and `cancelled`, sorted by `task_id`.
- Produces: `bash scripts/resume-task.sh --task-dir <abs>`. If `herdr agent get <slug>` succeeds, it focuses that agent's workspace and prints `focused`.
